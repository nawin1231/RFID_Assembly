# JSX to TSX (TypeScript) Implementation Plan

> **For the implementer:** Use `superpowers:executing-plans` (inline, main session). No subagents. One task at a time: build it, hand off the diff, wait for review, then start the next. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every source file in `frontend/src` from `.js`/`.jsx` to `.ts`/`.tsx` under `strict: true`, with typed API responses. The app behaves the same.

**Architecture:** Step-by-step migration with `allowJs`. Task 1 adds the toolchain. Then files move bottom-up: shared API types, then mocks, then components, then pages. After each task, the app, mock mode, the tests and the build all still work. The last task removes `allowJs`.

**Tech Stack:** Vite 8, Vitest 4, React 19, axios 1.x, ESLint 9 flat config, `typescript-eslint`, TypeScript 6.0.

**Spec:** No separate spec. The design was agreed in chat on 2026-09-29. It is recorded in [Design](#design) below. This is Phase 2 of `frontend/docs/2026-09-29-cra-to-vite.md:694`.

## Global Constraints

- `strict: true` from Task 1. Never turn it off for a file or folder.
- No `any`. `@typescript-eslint/no-explicit-any` is `error`. Every `as` cast and every `eslint-disable` gets a one-line comment that says why.
- Structure changes only. **No behavior change** in the conversion tasks. The only behavior change is Task 3, and it is a separate task.
- A type error that shows a real bug: if the fix changes nothing the user can see, fix it in the same step with the smallest change and add it to [Bugs found](#bugs-found). Otherwise, add a `// TODO(ts-bug-N)` comment plus a line in [Bugs found](#bugs-found), and keep the old behavior using a commented cast.
- API types come from `bruno/AYT-RFID/*.yml`. `src/types/api.ts` is the only place where they are defined. Pages and mocks both import from it.
- Rename files with `Move-Item` (PowerShell), never `git mv`. The user stages and commits.
- Each task must pass before hand-off, run from `frontend/`: `npm run typecheck`, `npm run lint`, `npm test -- --run`, `npm run build`. None of these touch a DB or a real API.
- Every task that touches a page or component ends with the user checking that screen in `npm run dev:mock`.
- Keep the root config files (`vite.config.js`, `eslint.config.js`, `postcss.config.js`, `tailwind.config.js`, `scripts/*.mjs`) as JS. They are outside `tsconfig` `include`.

## Review Focus

These failure modes are not covered by any automated test. Check them when reviewing each task:

1. **Error paths after typing `catch`.** Under `strict`, `err` is `unknown`. Code like `err.response.data.error` must become `axios.isAxiosError(err) ? err.response?.data : …`. The toast or message the user sees must stay the same. How to check: in mock mode, trigger a 404 (unknown lot or tag) on Register, ClearTag and ScanTag.
2. **Nullable API fields.** `summary.*`, `machine_no`, `remark`, `location_name`, `label_status` and `emp_id` can be `null`. When a type forces a `?? 0` or `?? '-'`, the rendered output must match the old output. How to check: the Dashboard "No matching lots" filter in mock mode shows 0, not blank.
3. **String vs number IDs from `<select>`.** `status_id` in forms and filters is a string today and is sent as a string. Do not "fix" this with `Number()`, because the backend and the mock parse it. How to check: ClearTag change-status and the Dashboard status filter still work in mock mode.
4. **Missing or corrupt `assy_user` in sessionStorage.** `readSessionUser()` must return `null` and never throw. Covered by a unit test in Task 9.
5. **Mock code must not leak into production.** Renaming the mock files must not break the dynamic import in `index.tsx`. How to check: `npm run build` runs `scripts/check-no-mocks.mjs` in every task. Task 10 changes the entry file, so check it there.

## Design

### D1. Toolchain (agreed in chat)

| Setting | Value | Why |
|---|---|---|
| `strict` | `true` | Real type safety (decision A) |
| `allowJs` / `checkJs` | `true` / `false` | JS and TS files live together. JS files are not type-checked. Removed in Task 19. |
| `noEmit`, `isolatedModules` | `true` | Vite transpiles. `tsc` only checks. |
| `jsx` | `react-jsx` | React 19 automatic runtime |
| `module` / `moduleResolution` | `ESNext` / `bundler` | Matches Vite |
| `types` | `vite/client`, `vitest/globals` | Types for `import.meta.env` and for the `describe`/`it` globals (`vite.config.js:18`) |
| `noUncheckedIndexedAccess` | off | Too noisy with arrays for now. Can be a later task. |
| `include` | `src` | Root config files stay JS |

ESLint uses `recommendedTypeChecked` for `ts/tsx`, with `no-explicit-any: error` and `no-misused-promises` set to `checksVoidReturn.attributes: false`, so `onClick={asyncFn}` is allowed. `no-floating-promises` stays on. Calls like `fetchX()` inside `useEffect` become `void fetchX()`. `build` runs `tsc --noEmit` first.

### D2. Where types live (for review)

| File | Holds | Used by |
|---|---|---|
| `src/types/api.ts` | Request and response shapes for every endpoint the frontend or the mocks use (not `/change-process`, which the frontend never calls) | pages, mock handlers |
| `src/mocks/types.ts` | `MockDb`, row types with extra DB columns (`LotRow`, `UserRow`, `StatusRow`), `Route`, `HandlerInput`, `HandlerResult` | mocks only |
| `src/config/session.ts` | `SESSION_KEY`, `readSessionUser(): User \| null` | `SecureRoute`, `Navbar`, `Sidebar`, `Management`, `mocks/session` |
| Component props | `interface XProps` declared in the same file, above the component | that file |

- There is no API layer. Pages call `backendApi.get<T>(…)` inline. Adding an API layer would be a refactor outside this goal.
- `readSessionUser` bends KISS a little: it is a new helper. The same `JSON.parse(sessionStorage.getItem('assy_user'))` code appears 4 times (`SecureRoute.jsx:10`, `Navbar.jsx:16,27`, `Sidebar.jsx:19,27`, `Management.jsx:22`). Without the helper, every copy needs its own cast. That is past the rule of three, so extracting it is the DRY choice.

### Decisions confirmed by the user (2026-09-29)

- Task 3 fixes the two mock drifts first, as its own TDD task in JS.
- `readSessionUser()` helper: extract it.
- ESLint `recommendedTypeChecked`: keep it, including `no-floating-promises`.
- TypeScript 6.0.

### D3. Order and rules (for review)

Bottom-up, so each file imports only typed modules: toolchain, then `types/api.ts` and config, then the mock contract fixes, then mocks, then session and app shell, then pages from small to large. A converted file that imports a `.js` file gets `any`. The order prevents that.

## Conversion rules (apply in every rename task)

1. Rename the file with `Move-Item`. Rename its test in the same task.
2. Keep import paths without extensions. They stay the same.
3. Delete `import React from 'react'` only when `React` is not used after the change. `react-jsx` does not need it. Keep named imports (`useState`, …).
4. Props: `interface XProps { … }` above the component, then `const X = ({ a, b }: XProps) => …`. Use `children: React.ReactNode`.
5. State: add a generic only when TS cannot infer it. `useState<Lot | null>(null)`, `useState<Status[]>([])`. Do not add a generic for `useState('')` or `useState(false)`.
6. Refs: DOM refs use `useRef<HTMLInputElement>(null)`. Timers use `useRef<ReturnType<typeof setTimeout> | null>(null)` and `useRef<ReturnType<typeof setInterval> | null>(null)`.
7. API calls: `backendApi.get<StatusRow[]>('/status')`, `backendApi.post<ScanResult>(url, body satisfies ScanRequest)`. Use the types in `src/types/api.ts`. Do not re-declare them.
8. Events declared outside JSX: `(e: React.ChangeEvent<HTMLInputElement>)`, `(e: React.KeyboardEvent<HTMLInputElement>)`. Inline handlers infer their types, so leave them as they are.
9. `catch (err)` stays untyped (`unknown`). Only `console.error(err)` is allowed on it, unless you narrow it with `axios.isAxiosError(err)`.
10. Async calls whose promise is ignored (in `useEffect` or `setInterval`) become `void fetchX()`.
11. Keep the formatting and comments (including the Thai ones) as they are. Do not reformat lines you did not change.
